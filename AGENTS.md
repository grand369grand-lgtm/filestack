# FileStack contributor notes

- UI: Expo SDK 58 / React Native, Android only (`expo.platforms` in `app.json`). Navigation is the small tab shell in `App.tsx`; this project does not use Expo Router.
- File access stays behind `src/fs/FsProvider`. The provider exposes one or more roots (`roots()`, `setRoot()`, `access()`, `requestAccess()`): the app's document directory, and on Android the shared `/storage/emulated/0` behind the all-files-access permission. Paths are always relative to the active root, so switching roots must not leak into the screens or the core.
- Every filesystem operation is a native call. `src/fs/device.ts` never walks a directory from JavaScript: `scan`, `read_text`, `mkdir`, `remove`, `rename`, `copy` and `exists` are Rust operations in `rust/src/fsops.rs`. Keep it that way — the point of the native core is one bridge call per user action.
- Core algorithms live in `rust/src/lib.rs`. There is no TypeScript mirror any more; do not add one. Run `npm test` (cargo test) after touching Rust.
- `src/core/display.ts` holds only render-time string helpers (`formatSize`, `categoryOf`, `extOf`). Anything that scans, ranks, sorts or aggregates belongs in Rust.
- The bridge is `modules/filecore`: Kotlin `FileCoreModule` → `FileCoreNative.invoke` → the JNI symbol in `rust/src/jni_bridge.rs`. The class name, package and method name are part of the symbol; renaming either side breaks the app at runtime.
- `npm run core:android` rebuilds `libfilecore.so` for the three ABIs. The `.so` files are gitignored, so run it after Rust changes and before Gradle. CI does this on every release.
- Typecheck with `npm run typecheck`.
- Android project files are generated by Expo Prebuild and are ignored by Git. Configure native changes through `app.json`, config plugins under `plugins/`, or the local module under `modules/`.
- Android release builds use the GitHub Actions workflow at `.github/workflows/android-release.yml`; no EAS login is required. Never commit signing keys, base64 keystores, passwords or personal access tokens.
- GitHub release uploads use the repository's built-in `GITHUB_TOKEN`. Use the local `gh` CLI sign-in script for creating/pushing a public repository; do not place a GitHub token in source or chat.
